# CMS integrity and homepage Hero media

Date: 2026-11-28

Scope: centralized Content Management, predefined section registry, Hero slide management, and public Hero images.

## 1. Problems and root causes

| Symptom | Actual cause | Fix |
| --- | --- | --- |
| Hero showed `12` records in the structure summary but only `6` in the Hero editor. | `WebsiteStructureService::serializeSection()` used `recordCount = $section->items->count()` (all rows), while `HeroSection.vue` filtered on `item.isSlide === true` (only real slides). CTA/control and legacy rows were counted but not listed. | Keep `recordCount` as the real total, add explicit `eligibleCount`, `visibleCount`, `hiddenCount`, `scheduledCount`, `expiredCount`, `slideCount` and `eligibleSlideCount`, and show the breakdown in the CMS UI. The Hero editor now lists every record and labels slide/control/legacy rows. |
| Several `إدارة المحتوى` buttons opened a 404. | Ten legacy sections existed in the database and some were publicly enabled, but were absent from `config/cms_structure.php`. The route constraint is generated from that registry, so their keys were rejected. | Registered `intro`, `areas`, `impact`, `framework`, `programs`, `targets`, `community`, `partners`, `knowledge` and `cta` with their real page/order/labels and `content => 'inline'`. No records were deleted, merged or duplicated. |
| Public Hero images did not load. | Seeded slides `slide-1`–`slide-5` had `media_id = null`, so the backend could not emit a media URL. The carousel also used a CSS custom property instead of a real `<img>`. | Added an idempotent repair seeder that assigns demo-library images only to seeded slides with no media, and changed the public carousel to render CMS-provided URLs as `<img>` with an explicit error fallback. |

## 2. Count definitions

All counts come from the backend and are derived from the same `HomepageSectionItem::scheduleState()` classification.

| Field | Definition |
| --- | --- |
| `recordCount` | Total rows in the section, including hidden, unpublished, scheduled, expired, CTA/control and legacy rows. Never silently filtered. |
| `eligibleCount` | Rows that are published and inside their display window now. |
| `visibleCount` | Eligible rows **and** the section is enabled/published **and** its page is enabled. |
| `hiddenCount` / `unpublishedCount` | Rows with `is_published = false`. Their data is preserved. |
| `scheduledCount` | Published rows whose `display_start_at` is in the future. |
| `expiredCount` | Published rows whose `display_end_at` is in the past. |
| `slideCount` | Hero rows where backend `isHeroSlide()` is true. Presentation controls (`primary`, `secondary`) and ticker-prefixed rows are not inferred as slides from their key alone. |
| `eligibleSlideCount` | Hero slides that are eligible now. |

## 3. `إدارة المحتوى` destination audit

Every button is rendered in `resources/js/Pages/Cms/ContentManagement/Index.vue` from `section.manageUrl` (line 343), which is generated by `WebsiteStructureService` from `route('cms.content.index', ['locale' => $locale, 'section' => $key])`. There are no hardcoded section destinations.

Common route contract for every URL below:

- URL pattern: `/{locale}/cms/content/{section}` (`ar` shown; `en` equivalent works).
- Route name: `cms.content.index`.
- Controller/action: `App\Http\Controllers\Cms\SectionContentController@index`.
- Route constraint: generated from `config('cms_structure.sections')`; unregistered keys return 404.
- Inertia page: `Cms/ContentManagement/Section`, which selects `HeroSection` for `slides`, `TickerSection` for `announcements`, and `DefaultSection` otherwise.
- View permission: `cms:homepage.view`.
- Write permissions on the same controller: `cms:homepage.update` for store, update, destroy, toggle, reorder, organization and presentation actions.
- Workspace: `/{locale}/cms/content-management` → `cms.content-management.index` → `StructureController@index`, permission `cms:website_structure.view`; page/section toggles and reorder use `cms:website_structure.update`.

## 4. Hero media repair and public delivery

### Seeder

```bash
php artisan db:seed --class=HeroMediaRepairSeeder --force --no-interaction
```

- Reads committed images from `storage/app/public/media/demo/images/`.
- Writes only to `storage/app/public/media/hero/{item_key}.jpg` on the public disk with visibility `public`.
- Assigns `media_id` only when a seeded slide key still has `media_id = null`. Existing editor choices are never overwritten.
- Restores a soft-deleted matching media row, avoids duplicate media rows, and flushes `HomepageService` cache.
- Re-running is idempotent. Generated JPG files are ignored by Git and regenerable from the committed demo images.

### End-to-end chain

1. `homepage_section_items.media_id` → `media.id` (`is_restricted = false`, public disk).
2. `HomepageService::serializeMedia()` emits `media.url` and localized `media.alt`.
3. Public `/{locale}` Inertia response exposes the section items with `slide`, `media` and alt text.
4. `ProHeroCarousel.vue` renders only backend `item.slide === true` rows, with `content.mediaUrl(item)` as `:src`, `content.mediaAlt(item)` as `:alt`, and `@error` fallback text.
5. `pcdr-prototype.css` uses `object-fit:cover`; the CSS `--photo` pseudo-element was removed.
6. `public/storage` points to `storage/app/public`, so the URLs load with no admin session.

No private-media authorization rule was changed and the public storage disk was not made global for restricted files.

## 5. Preserved controls

The three controls remain independent:

| Control | Route |
| --- | --- |
| Page Visibility | `PATCH /{locale}/cms/content-management/pages/{websitePage:key}/toggle` |
| Section Visibility | `PATCH /{locale}/cms/content-management/sections/{homepageSection:key}/toggle` |
| Homepage Content Display Selection | `PUT /{locale}/cms/content/{section}/presentation` |

Hiding a page or section only changes visibility metadata; it does not remove records. Item-level hiding uses `PATCH /{locale}/cms/content/{section}/{sectionItem}/toggle` and also preserves data.
